# 知识点提取指南

本指南定义了从技术对话中自动提取和标注知识点的规则和方法。

## 提取原则

### 1. 价值判断标准

**高价值对话特征：**
- ✅ 包含技术概念的深入解释
- ✅ 提供可运行的代码示例
- ✅ 解决了具体的技术问题
- ✅ 讨论了最佳实践或设计模式
- ✅ 对比分析了多种技术方案
- ✅ 包含调试或排错过程

**低价值对话特征：**
- ❌ 简单的事实查询（"Redis是什么"）
- ❌ 一问一答式的浅层对话
- ❌ 没有技术深度的闲聊
- ❌ 纯粹的环境配置指导（除非有特殊技巧）

### 2. 自动触发条件

满足以下任意2项即可触发记录提示：
1. 对话轮次 ≥ 5轮
2. 包含至少1个代码块（≥ 5行）
3. 用户明确表示"这个很重要"、"记录一下"
4. 讨论深度：AI给出了详细解释（回答字数 ≥ 300字）
5. 包含问题诊断过程（现象→原因→解决）

## 标签生成规则

### 主标签提取

**技术栈标签：**
- 格式：`tech:[技术名称]`
- 示例：`tech:spring-statemachine`、`tech:redis`
- 数量：1-2个主要技术栈

**领域标签：**
- 格式：`domain:[领域名称]`
- 示例：`domain:状态机`、`domain:缓存`
- 数量：1个核心领域

### 子标签提取

**概念标签：**
从对话中提取的关键技术术语
- 识别方法：查找专业名词、API名称、配置项
- 示例：`Guard条件`、`externalTransition`、`StateMachine`
- 数量：3-5个

**类型标签：**
标注对话的类型和特征
- `概念理解` - 询问是什么、为什么
- `代码实现` - 如何编写、如何使用
- `问题排查` - 调试、报错、异常
- `最佳实践` - 设计模式、优化
- `对比分析` - 方案比较

**场景标签：**
标注应用场景
- 示例：`订单流程`、`支付场景`、`用户认证`
- 提取来源：对话中提到的业务场景

### 难度等级判定

**入门级：**
- 讨论基础概念和定义
- 简单的Hello World示例
- 基本配置和使用方法

**进阶级：**
- 复杂的业务场景实现
- 多个特性的组合使用
- 常见问题的解决方案

**高级：**
- 架构设计和系统优化
- 源码分析和原理解释
- 性能调优和扩展性设计

## 内容提取规则

### 代码片段提取

**识别规则：**
- 提取所有```包裹的代码块
- 自动识别编程语言
- 保留完整的代码上下文

**标注信息：**
```markdown
#### [代码用途描述]
```[语言]
[代码内容]
```
**说明：**
- 功能：[...]
- 关键点：[...]
- 适用场景：[...]
```

**过滤规则：**
- 跳过非常简单的单行代码（除非是关键API）
- 合并同一主题的多个小代码块
- 标注代码的演进过程（错误示例→正确示例）

### 核心概念提取

**识别方法：**
1. 查找AI回答中的定义性句子
   - 包含"是指"、"意思是"、"可以理解为"
   - 使用了术语解释的句式

2. 提取概念之间的关系
   - "A包含B"、"A依赖B"
   - "A和B的区别是"

3. 整理成结构化格式
   ```markdown
   **概念名称：** 简洁的定义
   - 详细解释
   - 应用场景
   - 注意事项
   ```

### 问题解决过程提取

**适用场景：**
问题排查类对话

**提取结构：**
```markdown
### 问题现象
[用户描述的问题表现]

### 诊断过程
1. 检查点1 → 结果
2. 检查点2 → 结果
3. 定位原因

### 根本原因
[问题的根本原因分析]

### 解决方案
[具体的解决步骤]

### 预防措施
[避免类似问题的建议]
```

## 关联分析

### 相关对话识别

**关联规则：**
1. **技术栈相同** + **知识点相关**
   - 示例：都讨论Spring状态机的Guard条件

2. **问题类型相同** + **解决思路相似**
   - 示例：都是通过日志排查问题

3. **递进关系**
   - 后续对话是前次对话的深入或延伸
   - 示例：基础用法 → 高级特性

**关联强度：**
- 强关联（★★★）：同一技术的不同方面
- 中关联（★★）：相关技术的类似问题
- 弱关联（★）：通用方法论的应用

### 知识图谱构建

**节点类型：**
- 技术栈节点（Spring、Redis）
- 概念节点（状态机、缓存）
- 问题节点（性能优化、错误排查）
- 对话节点（具体的一次对话记录）

**边的关系：**
- `belongs_to`：对话属于某个技术栈
- `discusses`：对话讨论某个概念
- `relates_to`：对话之间的关联
- `solves`：对话解决某个问题

## 质量控制

### 记录完整性检查

生成记录前自动检查：
- ✅ 标题是否清晰描述了对话主题
- ✅ 至少包含1个核心概念或代码示例
- ✅ 知识点标签不少于3个
- ✅ 对话摘要准确反映了内容价值

### 标签一致性

**标签规范化：**
- 统一使用小写+连字符（spring-statemachine）
- 避免同义标签（缓存 vs cache → 统一使用中文）
- 定期合并相似标签

**层级检查：**
- 确保三级分类完整（技术栈→领域→知识点）
- 避免标签过于宽泛或过于细化

### 重复检测

**检测方法：**
1. 计算对话内容的相似度
2. 比较主题标签的重叠度
3. 检查时间窗口（1周内的相似对话）

**处理策略：**
- 高度相似（>80%）：询问是否需要记录
- 中度相似（50-80%）：记录但关联到已有对话
- 低度相似（<50%）：正常记录

## 自动化流程

### 实时分析

对话进行中实时分析：
```
每3轮对话后 → 评估对话价值
第5轮后 → 如果满足条件，准备记录提示
对话结束时 → 触发记录询问
```

### 后台处理

用户确认后的自动流程：
```
1. 提取对话内容（2秒）
2. 生成标签和分类（3秒）
3. 识别关联对话（2秒）
4. 生成Markdown文件（1秒）
5. 更新索引和统计（2秒）

总计：约10秒完成记录
```

记录完成后向用户展示：

提供反馈机制：
- "这次记录准确吗？"
- "标签是否合适？"
- "需要补充什么内容？"

### 标签学习

根据用户反馈优化：
- 记录用户修改的标签
- 学习用户的分类习惯
- 自动调整标签生成策略

定期生成报告：
- 最常讨论的技术主题
