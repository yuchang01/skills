## 知识要点总结

### 核心概念

**状态（State）：** 对象在某个时刻的情况
- 特点：互斥性、明确性
- 示例：订单的"已创建"、"已支付"、"已发货"

**事件（Event）：** 触发状态变化的动作
- 特点：原子性、可识别
- 示例：用户点击"支付"按钮

**转换（Transition）：** 状态之间的变化过程
- 组成：源状态 + 事件 + 目标状态
- 条件：可选的Guard条件

### 关键代码

```java
// 核心代码片段（已提炼）
public enum OrderState {
    CREATED, PAID, SHIPPED, COMPLETED
}

public enum OrderEvent {
    PAY, SHIP, COMPLETE
}
```

### 实用技巧

1. **状态设计原则：** 状态应该互斥且完整覆盖对象生命周期
2. **事件命名规范：** 使用动词，清晰表达意图
3. **避免的陷阱：** 不要设计过细的状态粒度

**第一级（章）：**

- 原则：按学习顺序划分大的知识模块

- 格式：`X.Y [节名]`
- 原则：按知识点或对话主题划分

**第三级（子节，可选）：**
- 格式：`X.Y.Z [子节名]`

## 章节更新机制

### 新对话的插入

当记录新对话时，AI会：

1. **判断章节归属：** 分析对话应该归入哪一章哪一节
2. **检查是否存在：** 查看该节是否已存在
3. **更新或创建：**
   - 如果节存在：追加到该节，作为新的对话轮次
   - 如果节不存在：创建新节
4. **更新主文件：** 在主书籍文件中更新目录和该节的摘要
5. **更新统计：** 更新学习进度、对话次数等统计数据
